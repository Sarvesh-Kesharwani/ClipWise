Build a web app for structured video watching and progress tracking.

## Product Goal
This app should help users watch long videos in smaller, manageable chunks instead of forcing them to watch a full 15-minute, 30-minute, or multi-hour video in one sitting.

The app should visually break a video into fixed-length clips (for example, 2-minute chunks), track which chunks were watched, how many times they were rewatched, and whether the user added a short summary for each chunk.

The user should be able to use:
1. Local videos loaded from a selected local folder or file picker
2. YouTube videos loaded by pasting a YouTube URL

---

## Core Features

### 1. Video Sources
Support two input methods:
- Local video files
- YouTube video links

Once a video is added, create a video record in the app.

---

### 2. Video Instances
A single video can have multiple "instances".

Each instance represents a separate tracking setup for the same video, with its own settings such as:
- clip size in minutes
- progress state
- watch counts
- summaries

Important rule:
- Once an instance is created, its clip size must be immutable
- The user must NOT be allowed to edit the clip size for an existing instance
- If the user wants a different clip size for the same video, they must create a new instance

When the user opens a video from the dashboard, first ask them which instance they want to open.

---

### 3. Clip Segmentation
For each video instance, split the full video into fixed-length clips based on a user-defined clip size in minutes.

Examples:
- 2-minute clips
- 5-minute clips
- 10-minute clips

The final clip can be shorter if the video duration does not divide evenly.

Also reflect these clip boundaries in the video progress bar so the user can clearly see the chunked structure.

---

### 4. Video Player Page
Create a video player page that feels similar to YouTube in usability and layout.

Requirements:
- Standard video player controls
- Progress bar showing clip segmentation
- Left-side panel showing all clips for the current video instance
- The clip list should appear in a tabbed or clearly separated side panel
- Show clips in a grid layout
- Each clip cell should display:
  - clip number or time range
  - watched or not watched status
  - watch count
  - whether a summary exists

---

### 5. Watch Tracking Logic
A clip should only be marked as "watched" if the user watches at least 80% of that clip.

Rules:
- If less than 80% of the clip is watched, do NOT mark it as watched
- If 80% or more is watched, mark it as watched
- Track how many times each clip has been watched
- Rewatching a clip should increase its watch count if the 80% threshold is met again

Make this logic robust enough to avoid accidental false positives from quick seeking/skipping.

---

### 6. Clip Summary
After a clip has been watched, the user should be able to enter a one-line summary for that clip.

Rules:
- A clip can be watched without being summarized
- A clip should only be considered "summarized" if the user actually enters and saves a summary
- Store the summary per clip, per instance

---

## Clip Color States

Use color to show the state of each clip cell.

Initial state:
- Red = not watched

After first successful watch:
- Yellow = watched, but no summary yet

After summary is added:
- Green = summarized

After additional rewatches:
Use higher-level colors for increased watch counts while still preserving the meaning of watched/summarized state.

Suggested progression:
- Red = not watched
- Yellow = watched once, no summary
- Green = summarized / completed baseline state
- Blue = watched 2 times
- Purple = watched 3 or more times

If needed, combine badges/labels/icons with color so state remains clear and not ambiguous.

Important:
The UI should clearly distinguish between:
- watched
- summarized
- rewatched multiple times

Do not let the color system become confusing.

---

## Dashboard / Home Page
Create a home page that acts as the main dashboard.

For each added video, show:
- video title
- source type (local or YouTube)
- thumbnail if available
- total number of instances
- overall progress
- quick access to open the video

When a user clicks a video, first show the list of instances for that video and let them choose which one to open.

### Overall Progress
Show overall progress on the dashboard using a clear formula.

Use a reasonable formula such as:
- watched progress = watched clips / total clips
- summarized progress = summarized clips / total clips

You may also show a combined progress score, but keep the logic simple and transparent in the UI.

---

## UX / Design Direction
Use a visual style inspired by Duolingo:
- playful and polished
- bright green primary theme
- rounded UI
- strong depth
- 3D-like buttons
- soft shadows
- highly motivating progress visuals

The app should feel rewarding and engaging, not like a dull tracker.

---

## Data / Persistence
Persist all important data so progress remains available across sessions:
- videos
- instances
- clip size
- clip watch state
- watch counts
- summaries
- progress metrics

---

## Important Behavior Details
- The app must be optimized for long-form video consumption
- The chunking system is the core feature, not a minor add-on
- The user should always feel they are progressing through small achievable units
- The interface should motivate the user to continue clip by clip
